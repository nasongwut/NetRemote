# NetRemote Relay Server — อธิบายการทำงาน

Relay Server คือ **ตัวกลาง** ที่ทำให้โปรแกรม NetRemote สองเครื่องเชื่อมต่อหากันได้ผ่านอินเทอร์เน็ต
โดย **ไม่ต้องเปิดพอร์ต / ตั้ง Port Forward** ที่เครื่องหรือ Router ของผู้ใช้
และ **Relay อ่านข้อมูลไม่ได้** เพราะทุกอย่างเข้ารหัส TLS จากต้นทางถึงปลายทาง (end-to-end)

> ตั้งแต่เวอร์ชันนี้ NetRemote เชื่อมต่อ **ผ่าน Relay เท่านั้น** (ไม่มีการเชื่อมต่อตรงในวง LAN)

---

## 1. ภาพรวม

```
  เครื่องที่ควบคุม (Client)                Relay Server (VPS)                 เครื่องที่ถูกควบคุม (Host)
 ┌──────────────────────┐            ┌───────────────────────┐            ┌──────────────────────┐
 │ NetRemote            │  ①ขอต่อ ID │  พอร์ต 5910 (TCP)     │ ⓪ ลงทะเบียน │ NetRemote            │
 │ "ควบคุมเครื่องอื่น"  │ ─────────▶ │  • ตาราง ID ออนไลน์   │ ◀───────── │ "ให้เครื่องอื่นควบคุม"│
 │                      │            │  • จับคู่ + ต่อท่อ    │  ค้างไว้ตลอด│  ID 497 196 653       │
 │                      │            │                       │ ② สั่งต่อ   │                      │
 │                      │            │                       │ ─────────▶ │                      │
 │                      │            │                       │ ③ ช่องข้อมูล│                      │
 │                      │ ◀═════════════════ ท่อ (pipe) ══════════════════▶│                      │
 │   🔒 TLS + รหัสผ่าน (end-to-end) — Relay เห็นแค่ข้อมูลที่เข้ารหัสแล้ว     │                      │
 └──────────────────────┘            │  พอร์ต 5911 (HTTP)    │            └──────────────────────┘
                                     │  หน้าเว็บมอนิเตอร์    │
                                     └───────────────────────┘
```

ทั้งสองเครื่อง **เชื่อมต่อออก (outbound)** ไปหา Relay เท่านั้น จึงผ่าน NAT / Firewall ของบ้านและออฟฟิศได้

## 2. ขั้นตอนการทำงาน

### ⓪ เครื่อง Host ลงทะเบียน ID
เมื่อกด **"เริ่มเปิดรับการเชื่อมต่อ"** โปรแกรม NetRemote จะ:
1. เชื่อมต่อ TCP ไป Relay แล้วส่ง `{"role":"host", "id":"497196653", "secret":"…", "key":"<Relay Key>"}`
2. Relay ตรวจ **Relay Key** และ **secret ของ ID**
   - ID ใหม่ → บันทึก hash ของ secret ลง `relay_ids.json` (ID นั้นผูกกับเครื่องนี้ถาวร)
   - ID เดิมแต่ secret ไม่ตรง → ปฏิเสธ (กันคนอื่นแอบใช้ ID ของเรา)
3. การเชื่อมต่อนี้ (**control channel**) ค้างไว้ตลอด — Host ส่ง `ping` ทุก 20 วินาที
   ถ้าหลุด Host จะเชื่อมต่อใหม่เองอัตโนมัติ (รอ 3 → 6 → … สูงสุด 60 วินาที)

### ① Client ขอเชื่อมต่อ ID
ผู้ใช้ใส่ **ID + รหัสผ่าน** แล้วกดเชื่อมต่อ → Client ส่ง `{"role":"client", "id":"497196653", "key":"…"}`

### ② Relay สั่ง Host เปิดช่องข้อมูล
Relay สร้าง **token** สุ่มแล้วส่งทาง control channel: `{"cmd":"connect", "token":"…", "from":"<IP ผู้ควบคุม>"}`

### ③ Host เปิดช่องข้อมูล แล้ว Relay ต่อท่อ
Host เชื่อมต่อใหม่ส่ง `{"role":"data", "token":"…"}` → Relay จับคู่ token แล้ว **ต่อท่อ (pipe)**
ระหว่าง socket ของ Client กับ Host — จากนี้ Relay แค่ส่งต่อไบต์ไปมา (ไม่ถอดรหัส)

### ④ ภายในท่อ (end-to-end ระหว่างสองเครื่อง)
1. **TLS handshake** — Host ใช้ Certificate ของตัวเอง, Client จำ fingerprint ไว้ (TOFU) ถ้าเปลี่ยนจะเตือน
2. **ยืนยันรหัสผ่านแบบ challenge–response** — Host ส่ง nonce, Client ตอบ
   `HMAC-SHA256(รหัสผ่าน, nonce + fingerprint ของ Certificate)` → **รหัสผ่านไม่ถูกส่งไปในเครือข่าย**
   และถ้ามีคนดักกลางทาง (MITM) fingerprint จะไม่ตรง ทำให้ยืนยันไม่ผ่าน
3. Host ถามผู้ใช้ "อนุญาตหรือไม่?" (ถ้าเปิดตัวเลือกนี้)
4. ส่งภาพหน้าจอ (เฉพาะส่วนที่เปลี่ยน, JPEG), เมาส์/คีย์บอร์ด, ping วัด Latency, รับ-ส่งไฟล์

---

### ⑤ เชื่อมต่อตรง (P2P) — ภาพ เมาส์ และไฟล์ ไม่วิ่งผ่าน Server
ทุกครั้งที่เชื่อมต่อ โปรแกรมจะลองต่อตรงระหว่างสองเครื่องอัตโนมัติ **ทุกทางพร้อมกัน** (ไม่เกิน ~3.5 วินาที):

| ทาง | ใช้ได้เมื่อ |
|---|---|
| ผู้ควบคุม → ปลายทาง | Firewall ของเครื่องปลายทางยอมรับการเชื่อมต่อขาเข้า |
| **ปลายทาง → ผู้ควบคุม** (ย้อนทาง) | Firewall ของเครื่องปลายทางบล็อก แต่ฝั่งผู้ควบคุมรับได้ |
| IP วง LAN | อยู่ในวง LAN / VPN เดียวกัน |
| IPv6 | ทั้งสองฝั่งมี IPv6 จาก ISP (ข้ามอินเทอร์เน็ตได้) |
| **UPnP** | Router เปิด UPnP — โปรแกรมขอเปิดพอร์ตชั่วคราวให้เอง (ปิดอัตโนมัติใน 25 วินาที) |

- ทางไหนสำเร็จก่อนใช้ทางนั้น (เครื่องที่ควบคุมเป็นผู้เลือก จึงได้ช่องเดียวเสมอ) · ไม่สำเร็จเลย → ใช้ Server ส่งต่อให้อัตโนมัติ
- ทุกช่องต้องมี token ครั้งเดียวจาก Server แล้วยังต้องผ่าน TLS + รหัสผ่าน — สแกนพอร์ตเข้ามาไม่ได้
- **หน้าเว็บ Server → ภาพรวม** แสดงว่าเซสชันไหน ⚡ เชื่อมต่อตรง / ผ่าน Relay และ**เหตุผล**ถ้าผ่าน Relay:
  - *เครื่องปลายทางใช้โปรแกรมเวอร์ชันเก่า* → อัปเดตโปรแกรมเครื่องนั้น (ต้องเวอร์ชัน 1.3 ขึ้นไปทั้งสองเครื่องจึงได้ครบทุกทาง)
  - *สองเครื่องต่อหากันตรงไม่ได้ (Firewall/Router)* → อนุญาต NetRemote ใน Firewall (Windows: Windows Security → Firewall → Allow an app)
    หรือเปิด UPnP ที่ Router · ถ้าอยู่หลัง CGNAT ของ ISP มือถือ/บางเจ้า จะต่อตรงข้ามอินเทอร์เน็ตไม่ได้ ต้องผ่าน Server
  - ดูรายละเอียดที่อยู่ที่ลองแล้วได้ใน log ของ Relay (บรรทัด "ต่อตรงไม่สำเร็จ")
- ทางเลือกสำหรับผู้ดูแล: `DIRECT_PORT=<พอร์ต>` + Port Forward ที่ Router ของเครื่องปลายทาง · ปิดการต่อตรง: `DIRECT_CONNECT=false`

## 3. โปรโตคอลระหว่างโปรแกรมกับ Relay

ทุกข้อความเป็น JSON 1 บรรทัด (ลงท้ายด้วย `\n`) — ส่งเฉพาะตอนเริ่มเชื่อมต่อ

| role / cmd | ทิศทาง | ข้อมูล | ผลลัพธ์ |
|---|---|---|---|
| `ping` | โปรแกรม → Relay | `key` | `{"ok":true, "v", "hosts", "sessions"}` — ใช้ตรวจสถานะ Relay (ป้ายสถานะในโปรแกรม) |
| `host` | Host → Relay | `id`, `secret`, `key`, `name` | `{"ok":true}` แล้วค้างการเชื่อมต่อไว้ |
| `client` | Client → Relay | `id`, `key` | `{"ok":true}` แล้วกลายเป็นท่อ หรือ `{"ok":false,"err":…}` |
| `connect` | Relay → Host | `token`, `from` | Host เปิดช่องข้อมูลใหม่ |
| `data` | Host → Relay | `token` | Relay ต่อท่อกับ Client |
| `ping`/`pong` | Host ↔ Relay | – | keep-alive ทุก 20 วินาที |

## 4. ความปลอดภัย

| สิ่งที่ป้องกัน | วิธี |
|---|---|
| คนนอกใช้ Relay ของเรา | **Relay Key** — ทุกการเชื่อมต่อต้องใส่ให้ตรง |
| แอบอ้าง ID ของเครื่องอื่น | ID ผูกกับ secret ของเครื่องที่ลงทะเบียนครั้งแรก (`relay_ids.json`) |
| Relay หรือผู้ดูแล Relay ดูหน้าจอ/ไฟล์ | TLS end-to-end ระหว่างสองเครื่อง — Relay เห็นแค่ข้อมูลเข้ารหัส |
| ดักรหัสผ่าน | ไม่ส่งรหัสผ่าน ใช้ HMAC ผูกกับ Certificate |
| เดารหัสผ่าน | Host บล็อก IP 60 วินาทีเมื่อผิด 3 ครั้ง + หน่วง 1 วินาทีทุกครั้งที่ผิด |
| ยิงการเชื่อมต่อถล่ม | Relay จำกัด 60 ครั้ง/นาที ต่อ IP, จำกัดจำนวนเซสชันพร้อมกัน |
| ไม่มีพอร์ตเปิดบนเครื่องผู้ใช้ | Host ไม่ listen พอร์ตใด ๆ เลย — เชื่อมต่อออกไปหา Relay อย่างเดียว |

> ⚠ ข้อความช่วงเริ่มต้น (ID, Relay Key) ระหว่างโปรแกรมกับ Relay ไม่ได้เข้ารหัส — Relay Key จึงเป็นแค่ "กุญแจเข้าใช้ Relay"
> ส่วนการเข้าเครื่องจริงยังต้องใช้รหัสผ่านของแต่ละเครื่อง และข้อมูลจริงเข้ารหัส TLS เสมอ

## 5. ไฟล์ตั้งค่า `.env`

Relay อ่านไฟล์ `.env` ที่อยู่โฟลเดอร์เดียวกับ `relay_server.py` อัตโนมัติ (หรือระบุ `--env path`)
คัดลอกจาก `.env.example` แล้วแก้ไข — **ห้ามอัปโหลด `.env` ขึ้น GitHub**

| ตัวแปร | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `RELAY_PORT` | `5910` | พอร์ตที่โปรแกรม NetRemote เชื่อมต่อเข้ามา (เปิดใน Firewall) |
| `RELAY_KEY` | – | รหัสใช้ Relay — **ต้องตรงกับ `RELAY_KEY` ในไฟล์ `.env` ของโปรแกรม NetRemote** |
| `RELAY_STORE` | `relay_ids.json` | ไฟล์เก็บ ID ที่ลงทะเบียน |
| `RELAY_MAX_SESSIONS` | `50` | เซสชันพร้อมกันสูงสุด |
| `RELAY_WEB_PORT` | `5911` | พอร์ตหน้ามอนิเตอร์ (`0` = ปิด) |
| `RELAY_WEB_BIND` | `127.0.0.1` | `127.0.0.1` = ดูได้จากเครื่อง Relay เท่านั้น, `0.0.0.0` = เปิดให้เครื่องอื่น |
| `RELAY_ADMIN_KEY` | (= `RELAY_KEY`) | รหัสเข้าหน้าเว็บจัดการ Server |
| `RELAY_UPDATES_DIR` | `updates/` | โฟลเดอร์ไฟล์อัปเดตโปรแกรม (ดูหัวข้อ 8) |

ลำดับความสำคัญ: **ตัวเลือกคำสั่ง (`--key`)** > **ตัวแปร environment** > **ไฟล์ `.env`** > ค่าเริ่มต้น

ฝั่งโปรแกรม NetRemote ใช้ไฟล์ `.env` ของตัวเอง (`Remote Desktop/.env`) ใส่ `RELAY_ADDR` และ `RELAY_KEY`
ถ้าวางไว้ตอน Build จะถูก **ฝังในโปรแกรม** — ผู้ใช้ติดตั้งแล้วใช้ได้เลยไม่ต้องตั้งค่า

## 6. หน้าเว็บจัดการ Server (พอร์ต 5911)

เปิด `http://localhost:5911` บนเครื่องที่รัน Relay → หน้า **เข้าสู่ระบบ** → ใส่รหัส Admin
เมนูด้านซ้าย (Sidebar) มี 3 หน้า · ปุ่ม **English / ไทย** สลับภาษาได้ที่มุมล่างซ้าย (และในหน้าเข้าสู่ระบบ)

**หน้าเข้าสู่ระบบ**
- รหัสผ่าน = `RELAY_ADMIN_KEY` ใน `Server/.env` (ถ้าไม่ได้ตั้ง ใช้ค่าเดียวกับ `RELAY_KEY`)
- ปุ่ม 👁 แสดงรหัสผ่าน · แจ้งเตือน Caps Lock · "จดจำการเข้าสู่ระบบ 30 วัน"
- ใส่ผิด 5 ครั้ง ล็อก 60 วินาที · รีสตาร์ต Relay แล้วยังอยู่ในระบบ · เปลี่ยนรหัส Admin = ทุกคนต้องเข้าสู่ระบบใหม่

**① ภาพรวม** — เครื่องออนไลน์, เซสชันที่กำลังเชื่อมต่อ (⚡ เชื่อมต่อตรง / ผ่าน Relay), ความเร็ว, ข้อมูลรวม,
เวอร์ชันโปรแกรมของแต่ละเครื่อง, เหตุการณ์ล่าสุด + ปุ่ม **ตัดการเชื่อมต่อ / ตัดออก**

**② Server Monitor** — ทรัพยากรของเครื่องที่รัน Relay (อัปเดตทุก 2 วินาที, กราฟย้อนหลัง 10 นาที)
- **CPU** (% + load average) · **RAM** (ใช้ไป / ทั้งหมด, swap) · **HARDDISK** (ทุกไดรฟ์, ไดรฟ์ที่เก็บ Relay)
- **NETWORK** (รับ/ส่งต่อวินาทีของการ์ดเครือข่าย) · กราฟ **ข้อมูลผ่าน Relay** · ข้อมูลเครื่อง (OS, Python, เวลาเปิดเครื่อง, หน่วยความจำของ Relay)
- ใช้งานได้ทันทีบน Linux / macOS โดยไม่ต้องติดตั้งอะไร · ติดตั้ง `pip install psutil` ได้ถ้าต้องการค่าที่แม่นยำขึ้น (และรองรับ Windows ครบ)

**③ ตั้งค่า Server** — แก้ค่าในไฟล์ `.env` ผ่านหน้าเว็บ
| ป้าย | ความหมาย |
|---|---|
| **มีผลทันที** | `RELAY_KEY`, `RELAY_MAX_SESSIONS`, `RELAY_UPDATES_DIR`, `RELAY_ADMIN_KEY` — กดบันทึกแล้วใช้ได้เลย |
| **ต้องรีสตาร์ต** | `RELAY_PORT`, `RELAY_WEB_PORT`, `RELAY_WEB_BIND`, `RELAY_STORE` — บันทึกแล้วกด **รีสตาร์ต Relay** |
| 🔒 **ตั้งจาก command line / environment** | แก้จากหน้าเว็บไม่ได้ (ค่าที่ส่งตอนสั่งรันมีผลเหนือกว่า) |
- **โหลดค่าใหม่จากไฟล์** — ถ้าแก้ไฟล์ `.env` เองด้วย text editor กดปุ่มนี้เพื่อใช้ค่าใหม่โดยไม่ต้องรีสตาร์ต
- **รีสตาร์ต Relay** — เครื่องที่ออนไลน์จะหลุดชั่วครู่แล้วต่อกลับเอง · ถ้าเปลี่ยนพอร์ตหน้าเว็บ จะพาไปพอร์ตใหม่ให้อัตโนมัติ
- การบันทึกเก็บคอมเมนต์และลำดับเดิมในไฟล์ `.env` ไว้ · ⚠ เปลี่ยน `RELAY_KEY` แล้วทุกเครื่องต้องใส่ Server Key ใหม่

API (ใช้ Basic auth ได้ เช่น `curl -u admin:<รหัส>`):
`GET /api/state` · `GET /api/system` · `GET /api/settings` · `POST /api/settings` `{"values": {...}}` ·
`POST /api/reload` · `POST /api/restart` · `POST /api/kick` `{"sid": "..."}` หรือ `{"host": "<ID>"}`

ดูจากเครื่องอื่น: `ssh -L 5911:localhost:5911 user@relay` แล้วเปิด `http://localhost:5911` (แนะนำ)
หรือตั้ง "เปิดให้ใครดูหน้าเว็บ" = ทุกเครื่องในเครือข่าย (`RELAY_WEB_BIND=0.0.0.0`) — ต้องเข้าสู่ระบบด้วยรหัส Admin เสมอ

## 7. ติดตั้ง

### ทดลองบน Mac / เครื่องในออฟฟิศ
```bash
cd "Remote Desktop/Server"
cp .env.example .env          # ครั้งแรก: แก้ RELAY_KEY ให้เป็นรหัสของคุณ (หรือใช้ .env ที่สร้างให้แล้ว)
./start_server.sh             # สร้าง .venv + ติดตั้ง requirements.txt (ครั้งแรก) → activate → เปิด Server เบื้องหลัง
./start_server.sh reload      # ปิดแล้วเปิดใหม่ (หลังแก้ .env / อัปเดตไฟล์)
./start_server.sh stop        # ปิด · status = ดูสถานะ · log = ดู log สด · fg = เปิดอยู่หน้า Terminal
# Windows: ใช้ start_server.bat แบบเดียวกัน (start / reload / stop / status / log / fg)
```
โปรแกรม NetRemote ทุกเครื่องตั้ง `RELAY_ADDR=<IP เครื่องที่รัน Relay>:5910`
(ถ้าจะใช้ข้ามอินเทอร์เน็ต ต้อง Port Forward TCP 5910 ที่ Router มาที่เครื่องนี้)

### บน VPS (Ubuntu / Debian) — แนะนำสำหรับใช้งานจริง
```bash
sudo apt install -y python3-pip && sudo pip3 install -r requirements.txt   # ไม่บังคับ (psutil สำหรับหน้า Server Monitor)
sudo mkdir -p /opt/netremote-relay
sudo cp -r relay_server.py .env updates /opt/netremote-relay/
sudo useradd -r -s /usr/sbin/nologin netremote          # ผู้ใช้สำหรับรัน Relay
sudo chown -R netremote:netremote /opt/netremote-relay   # ให้หน้าเว็บบันทึกการตั้งค่าได้
sudo chmod 600 /opt/netremote-relay/.env
sudo cp netremote-relay.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now netremote-relay
sudo ufw allow 5910/tcp                       # และเปิดใน Firewall ของผู้ให้บริการ
sudo journalctl -u netremote-relay -f         # ดู log
```
สเปกต่ำสุดก็พอ (1 vCPU / 512 MB) — ใช้แค่ Python 3.8+ ไม่ต้องติดตั้งไลบรารีเพิ่ม (`requirements.txt` มีแค่ psutil ซึ่งไม่บังคับ)

> อัปเกรดจากเวอร์ชันก่อน: คัดลอกไฟล์ `netremote-relay.service` ใหม่ + ทำคำสั่ง `useradd` และ `chown` ด้านบน แล้ว `sudo systemctl daemon-reload && sudo systemctl restart netremote-relay`
Bandwidth: รีโมทปกติ ~0.2–3 Mbps ต่อเซสชัน, รับ-ส่งไฟล์ใช้ตามขนาดไฟล์ — เลือก VPS ใกล้ผู้ใช้ (ไทย/สิงคโปร์) Latency จะต่ำ

## 8. แจกอัปเดตโปรแกรม (อัปเดตอัตโนมัติ)

**ฝั่งผู้ดูแล — หน้าเว็บ Server → เมนู "อัปเดตโปรแกรม"**
1. แก้ `VERSION = "x.y"` ใน `remote_desktop.py` → push ขึ้น GitHub ให้ Actions Build (หรือ Build เอง)
2. ในหน้า "อัปเดตโปรแกรม" กด **อัปโหลด…** ทีละแพลตฟอร์ม:
   Windows = `NetRemote.exe` · macOS Apple Silicon = `NetRemote-macOS-arm64.dmg` · macOS Intel = `…-x86_64.dmg`
   · Source = `remote_desktop.py` (สำหรับเครื่องที่รันจาก Run on Mac.command / Run on Windows.bat)
3. ใส่ **เลขเวอร์ชัน** (ต้องตรงกับ VERSION ในไฟล์ที่ Build) + **มีอะไรใหม่** → กด **เผยแพร่อัปเดต**
- หน้านี้แสดงเวอร์ชันของทุกเครื่องที่ออนไลน์ (ล่าสุด / รออัปเดต) และไฟล์ในโฟลเดอร์ `updates/` (ลบได้)
- **หยุดแจกอัปเดต** = ลบ `latest.json` (ไฟล์ยังอยู่) · ไม่ต้องรีสตาร์ต Relay
- ไม่ใช้หน้าเว็บก็ได้: คัดลอกไฟล์ไปไว้ใน `Server/updates/` แล้วสร้าง `latest.json` ตาม `latest.json.example`

**ฝั่งผู้ใช้ — ไม่ต้องทำอะไร**
- โปรแกรมตรวจหาอัปเดตตอนเปิด และทุก 1 ชั่วโมง → เจอเวอร์ชันใหม่ **ดาวน์โหลดเองในเบื้องหลัง** (ตรวจความสมบูรณ์ของไฟล์)
- เสร็จแล้วมีป้ายสีเขียว **"↻ Restart to update to x.y"** มุมขวาบน → กดเพื่อติดตั้ง + เปิดใหม่ทันที
  หรือไม่กดก็ได้ — **จะติดตั้งให้อัตโนมัติตอนปิดโปรแกรม**
- Windows: แทนที่ `NetRemote.exe` ตัวเดิม · macOS: แทนที่ `NetRemote.app` จากไฟล์ .dmg · Source: แทนที่ `remote_desktop.py`
- เครื่องที่ไม่มีคนเฝ้า (เปิดไว้ให้รีโมทเข้า): ใส่ `AUTO_UPDATE=auto` ในไฟล์ `.env` ของโปรแกรม
  → ติดตั้ง + เปิดใหม่เองทันทีที่ไม่มีใครรีโมทอยู่
- ⚠ macOS: ถ้าโปรแกรมไม่ได้ลงลายเซ็น Apple Developer ID หลังอัปเดตอาจต้องเปิดสิทธิ์
  Screen Recording / Accessibility ให้ NetRemote ใหม่ (System Settings → Privacy & Security)
- ถ้าโฟลเดอร์ที่วางโปรแกรมเขียนไม่ได้ (เช่น Program Files) จะดาวน์โหลดลง Downloads ให้ติดตั้งเองแทน

## 9. แก้ปัญหา

| อาการ (ในโปรแกรม NetRemote) | สาเหตุ / วิธีแก้ |
|---|---|
| ป้ายแดง "Relay: เชื่อมต่อไม่ได้" — Connection refused | Relay ไม่ได้รัน หรือพอร์ตผิด → ตรวจ `systemctl status netremote-relay` |
| … — timed out | Firewall ปิดพอร์ต 5910 (ทั้งใน VPS และของผู้ให้บริการ) |
| … — Name or service not known | `RELAY_ADDR` พิมพ์ชื่อโดเมนผิด |
| "Relay Key ไม่ถูกต้อง" | `RELAY_KEY` ในโปรแกรม ≠ ใน `Server/.env` |
| "ไม่พบเครื่อง ID … " | เครื่องปลายทางไม่ได้เปิดโปรแกรม NetRemote หรือออฟไลน์ |
| "ID นี้ถูกใช้โดยเครื่องอื่นแล้ว" | กด "สร้าง ID ใหม่" ในโปรแกรม (หรือลบ ID นั้นใน `relay_ids.json` แล้วรีสตาร์ต Relay) |
| "เครื่องปลายทางไม่ตอบสนอง" | Host หลุดจาก Relay ชั่วคราว รอสักครู่แล้วลองใหม่ |
| เครื่องไม่อัปเดต | ยังไม่ได้กด "เผยแพร่อัปเดต" · เลขเวอร์ชันต้องมากกว่า `VERSION` ของโปรแกรมในเครื่อง · ต้องอัปโหลดไฟล์ของแพลตฟอร์มนั้น (Windows / macOS / Source) · โปรแกรมเวอร์ชันต่ำกว่า 1.4 ต้องติดตั้งเองครั้งแรก |
| แสดง "☁ ผ่าน Server" ทั้งที่อยู่วง LAN เดียวกัน | Firewall ของเครื่องปลายทางบล็อกการเชื่อมต่อขาเข้า (macOS: System Settings → Network → Firewall / Windows: อนุญาต NetRemote) หรือ Wi-Fi เปิด Client Isolation |
| "ไฟล์เสียระหว่างดาวน์โหลด" | ไฟล์ใน `updates/` ถูกแก้ระหว่างโหลด → ลองใหม่ |
