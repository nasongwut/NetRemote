# NetRemote Relay Server — อธิบายการทำงาน

Relay Server คือ **ตัวกลาง** ที่ทำให้โปรแกรม NetRemote สองเครื่องเชื่อมต่อหากันได้ผ่านอินเทอร์เน็ต
โดย **ไม่ต้องเปิดพอร์ต / ตั้ง Port Forward** ที่เครื่องหรือ Router ของผู้ใช้
และ **Relay อ่านข้อมูลไม่ได้** เพราะทุกอย่างเข้ารหัส TLS จากต้นทางถึงปลายทาง (end-to-end)

> ตั้งแต่เวอร์ชันนี้ NetRemote เชื่อมต่อ **ผ่าน Relay เท่านั้น** (ไม่มีการเชื่อมต่อตรงในวง LAN)

---

## 1. ภาพรวม

```
  เครื่องที่ควบคุม (Client)                Relay Server (VPS)                 เครื่องที่ถูกควบคุม (Host)
 ┌──────────────────────┐            ┌───────────────────────┐            ┌──────────────────────┐
 │ NetRemote            │  ①ขอต่อ ID │  พอร์ต 5910 (TCP)     │ ⓪ ลงทะเบียน │ NetRemote            │
 │ "ควบคุมเครื่องอื่น"  │ ─────────▶ │  • ตาราง ID ออนไลน์   │ ◀───────── │ "ให้เครื่องอื่นควบคุม"│
 │                      │            │  • จับคู่ + ต่อท่อ    │  ค้างไว้ตลอด│  ID 497 196 653       │
 │                      │            │                       │ ② สั่งต่อ   │                      │
 │                      │            │                       │ ─────────▶ │                      │
 │                      │            │                       │ ③ ช่องข้อมูล│                      │
 │                      │ ◀═════════════════ ท่อ (pipe) ══════════════════▶│                      │
 │   🔒 TLS + รหัสผ่าน (end-to-end) — Relay เห็นแค่ข้อมูลที่เข้ารหัสแล้ว     │                      │
 └──────────────────────┘            │  พอร์ต 5911 (HTTP)    │            └──────────────────────┘
                                     │  หน้าเว็บมอนิเตอร์    │
                                     └───────────────────────┘
```

ทั้งสองเครื่อง **เชื่อมต่อออก (outbound)** ไปหา Relay เท่านั้น จึงผ่าน NAT / Firewall ของบ้านและออฟฟิศได้

## 2. ขั้นตอนการทำงาน

### ⓪ เครื่อง Host ลงทะเบียน ID
เมื่อกด **"เริ่มเปิดรับการเชื่อมต่อ"** โปรแกรม NetRemote จะ:
1. เชื่อมต่อ TCP ไป Relay แล้วส่ง `{"role":"host", "id":"497196653", "secret":"…", "key":"<Relay Key>"}`
2. Relay ตรวจ **Relay Key** และ **secret ของ ID**
   - ID ใหม่ → บันทึก hash ของ secret ลง `relay_ids.json` (ID นั้นผูกกับเครื่องนี้ถาวร)
   - ID เดิมแต่ secret ไม่ตรง → ปฏิเสธ (กันคนอื่นแอบใช้ ID ของเรา)
3. การเชื่อมต่อนี้ (**control channel**) ค้างไว้ตลอด — Host ส่ง `ping` ทุก 20 วินาที
   ถ้าหลุด Host จะเชื่อมต่อใหม่เองอัตโนมัติ (รอ 3 → 6 → … สูงสุด 60 วินาที)

### ① Client ขอเชื่อมต่อ ID
ผู้ใช้ใส่ **ID + รหัสผ่าน** แล้วกดเชื่อมต่อ → Client ส่ง `{"role":"client", "id":"497196653", "key":"…"}`

### ② Relay สั่ง Host เปิดช่องข้อมูล
Relay สร้าง **token** สุ่มแล้วส่งทาง control channel: `{"cmd":"connect", "token":"…", "from":"<IP ผู้ควบคุม>"}`

### ③ Host เปิดช่องข้อมูล แล้ว Relay ต่อท่อ
Host เชื่อมต่อใหม่ส่ง `{"role":"data", "token":"…"}` → Relay จับคู่ token แล้ว **ต่อท่อ (pipe)**
ระหว่าง socket ของ Client กับ Host — จากนี้ Relay แค่ส่งต่อไบต์ไปมา (ไม่ถอดรหัส)

### ④ ภายในท่อ (end-to-end ระหว่างสองเครื่อง)
1. **TLS handshake** — Host ใช้ Certificate ของตัวเอง, Client จำ fingerprint ไว้ (TOFU) ถ้าเปลี่ยนจะเตือน
2. **ยืนยันรหัสผ่านแบบ challenge–response** — Host ส่ง nonce, Client ตอบ
   `HMAC-SHA256(รหัสผ่าน, nonce + fingerprint ของ Certificate)` → **รหัสผ่านไม่ถูกส่งไปในเครือข่าย**
   และถ้ามีคนดักกลางทาง (MITM) fingerprint จะไม่ตรง ทำให้ยืนยันไม่ผ่าน
3. Host ถามผู้ใช้ "อนุญาตหรือไม่?" (ถ้าเปิดตัวเลือกนี้)
4. ส่งภาพหน้าจอ (เฉพาะส่วนที่เปลี่ยน, JPEG), เมาส์/คีย์บอร์ด, ping วัด Latency, รับ-ส่งไฟล์

## 3. โปรโตคอลระหว่างโปรแกรมกับ Relay

ทุกข้อความเป็น JSON 1 บรรทัด (ลงท้ายด้วย `\n`) — ส่งเฉพาะตอนเริ่มเชื่อมต่อ

| role / cmd | ทิศทาง | ข้อมูล | ผลลัพธ์ |
|---|---|---|---|
| `ping` | โปรแกรม → Relay | `key` | `{"ok":true, "v", "hosts", "sessions"}` — ใช้ตรวจสถานะ Relay (ป้ายสถานะในโปรแกรม) |
| `host` | Host → Relay | `id`, `secret`, `key`, `name` | `{"ok":true}` แล้วค้างการเชื่อมต่อไว้ |
| `client` | Client → Relay | `id`, `key` | `{"ok":true}` แล้วกลายเป็นท่อ หรือ `{"ok":false,"err":…}` |
| `connect` | Relay → Host | `token`, `from` | Host เปิดช่องข้อมูลใหม่ |
| `data` | Host → Relay | `token` | Relay ต่อท่อกับ Client |
| `ping`/`pong` | Host ↔ Relay | – | keep-alive ทุก 20 วินาที |

## 4. ความปลอดภัย

| สิ่งที่ป้องกัน | วิธี |
|---|---|
| คนนอกใช้ Relay ของเรา | **Relay Key** — ทุกการเชื่อมต่อต้องใส่ให้ตรง |
| แอบอ้าง ID ของเครื่องอื่น | ID ผูกกับ secret ของเครื่องที่ลงทะเบียนครั้งแรก (`relay_ids.json`) |
| Relay หรือผู้ดูแล Relay ดูหน้าจอ/ไฟล์ | TLS end-to-end ระหว่างสองเครื่อง — Relay เห็นแค่ข้อมูลเข้ารหัส |
| ดักรหัสผ่าน | ไม่ส่งรหัสผ่าน ใช้ HMAC ผูกกับ Certificate |
| เดารหัสผ่าน | Host บล็อก IP 60 วินาทีเมื่อผิด 3 ครั้ง + หน่วง 1 วินาทีทุกครั้งที่ผิด |
| ยิงการเชื่อมต่อถล่ม | Relay จำกัด 60 ครั้ง/นาที ต่อ IP, จำกัดจำนวนเซสชันพร้อมกัน |
| ไม่มีพอร์ตเปิดบนเครื่องผู้ใช้ | Host ไม่ listen พอร์ตใด ๆ เลย — เชื่อมต่อออกไปหา Relay อย่างเดียว |

> ⚠ ข้อความช่วงเริ่มต้น (ID, Relay Key) ระหว่างโปรแกรมกับ Relay ไม่ได้เข้ารหัส — Relay Key จึงเป็นแค่ "กุญแจเข้าใช้ Relay"
> ส่วนการเข้าเครื่องจริงยังต้องใช้รหัสผ่านของแต่ละเครื่อง และข้อมูลจริงเข้ารหัส TLS เสมอ

## 5. ไฟล์ตั้งค่า `.env`

Relay อ่านไฟล์ `.env` ที่อยู่โฟลเดอร์เดียวกับ `relay_server.py` อัตโนมัติ (หรือระบุ `--env path`)
คัดลอกจาก `.env.example` แล้วแก้ไข — **ห้ามอัปโหลด `.env` ขึ้น GitHub**

| ตัวแปร | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `RELAY_PORT` | `5910` | พอร์ตที่โปรแกรม NetRemote เชื่อมต่อเข้ามา (เปิดใน Firewall) |
| `RELAY_KEY` | – | รหัสใช้ Relay — **ต้องตรงกับ `RELAY_KEY` ในไฟล์ `.env` ของโปรแกรม NetRemote** |
| `RELAY_STORE` | `relay_ids.json` | ไฟล์เก็บ ID ที่ลงทะเบียน |
| `RELAY_MAX_SESSIONS` | `50` | เซสชันพร้อมกันสูงสุด |
| `RELAY_WEB_PORT` | `5911` | พอร์ตหน้ามอนิเตอร์ (`0` = ปิด) |
| `RELAY_WEB_BIND` | `127.0.0.1` | `127.0.0.1` = ดูได้จากเครื่อง Relay เท่านั้น, `0.0.0.0` = เปิดให้เครื่องอื่น |
| `RELAY_ADMIN_KEY` | (= `RELAY_KEY`) | รหัสเข้าหน้ามอนิเตอร์ |
| `RELAY_UPDATES_DIR` | `updates/` | โฟลเดอร์ไฟล์อัปเดตโปรแกรม (ดูหัวข้อ 8) |

ลำดับความสำคัญ: **ตัวเลือกคำสั่ง (`--key`)** > **ตัวแปร environment** > **ไฟล์ `.env`** > ค่าเริ่มต้น

ฝั่งโปรแกรม NetRemote ใช้ไฟล์ `.env` ของตัวเอง (`Remote Desktop/.env`) ใส่ `RELAY_ADDR` และ `RELAY_KEY`
ถ้าวางไว้ตอน Build จะถูก **ฝังในโปรแกรม** — ผู้ใช้ติดตั้งแล้วใช้ได้เลยไม่ต้องตั้งค่า

## 6. หน้าเว็บมอนิเตอร์ (พอร์ต 5911)

เปิด `http://localhost:5911` บนเครื่องที่รัน Relay (อัปเดตทุก 2 วินาที):

- **ตัวเลขสรุป** — เครื่องออนไลน์, เซสชันที่กำลังเชื่อมต่อ, ความเร็วรวม, ข้อมูลรวม, เวลาทำงาน, Relay Key ผิดกี่ครั้ง
- **กำลังเชื่อมต่ออยู่** — IP ผู้ควบคุม → เครื่องปลายทาง (ชื่อ + ID), เวลา, ข้อมูล, ความเร็ว ↑↓ + ปุ่ม **ตัดการเชื่อมต่อ**
- **เครื่องที่ออนไลน์** — ID, ชื่อเครื่อง, IP, ออนไลน์มานานเท่าไร, ว่าง/กำลังถูกควบคุม + ปุ่ม **ตัดออก**
- **เหตุการณ์ล่าสุด** — ออนไลน์/ออฟไลน์, เริ่ม/เลิกเชื่อมต่อ, Relay Key ผิด, ID ชน

API: `GET /api/state` (JSON), `POST /api/kick` `{"sid": "..."}` หรือ `{"host": "<ID>"}`

ดูจากเครื่องอื่น: `ssh -L 5911:localhost:5911 user@relay` แล้วเปิด `http://localhost:5911` (แนะนำ)
หรือตั้ง `RELAY_WEB_BIND=0.0.0.0` (ต้องใส่รหัส Admin — ชื่อผู้ใช้อะไรก็ได้)

## 7. ติดตั้ง

### ทดลองบน Mac / เครื่องในออฟฟิศ
```bash
cd "Remote Desktop/relay"
cp .env.example .env        # แก้ RELAY_KEY ให้เป็นรหัสของคุณ (หรือใช้ .env ที่สร้างให้แล้ว)
python3 relay_server.py
```
โปรแกรม NetRemote ทุกเครื่องตั้ง `RELAY_ADDR=<IP เครื่องที่รัน Relay>:5910`
(ถ้าจะใช้ข้ามอินเทอร์เน็ต ต้อง Port Forward TCP 5910 ที่ Router มาที่เครื่องนี้)

### บน VPS (Ubuntu / Debian) — แนะนำสำหรับใช้งานจริง
```bash
sudo mkdir -p /opt/netremote-relay
sudo cp -r relay_server.py .env updates /opt/netremote-relay/
sudo chmod 600 /opt/netremote-relay/.env
sudo cp netremote-relay.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now netremote-relay
sudo ufw allow 5910/tcp                       # และเปิดใน Firewall ของผู้ให้บริการ
sudo journalctl -u netremote-relay -f         # ดู log
```
สเปกต่ำสุดก็พอ (1 vCPU / 512 MB) — ใช้แค่ Python 3.8+ ไม่ต้องติดตั้งไลบรารีเพิ่ม
Bandwidth: รีโมทปกติ ~0.2–3 Mbps ต่อเซสชัน, รับ-ส่งไฟล์ใช้ตามขนาดไฟล์ — เลือก VPS ใกล้ผู้ใช้ (ไทย/สิงคโปร์) Latency จะต่ำ

## 8. แจกอัปเดตโปรแกรม NetRemote

Relay ทำหน้าที่เป็นเซิร์ฟเวอร์อัปเดตด้วย — โปรแกรม NetRemote จะถาม Relay ว่ามีเวอร์ชันใหม่หรือไม่
**ตอนเปิดโปรแกรม และทุก 6 ชั่วโมง** (หรือกด "ตรวจสอบอัปเดต" ในแท็บ "ตั้งค่า Server")
ถ้ามี จะขึ้นป้าย **⬆ มีอัปเดต x.y** มุมบน → กด "ดาวน์โหลด" → ไฟล์ลง `Downloads` พร้อมตรวจ SHA-256
(Mac เปิดไฟล์ .dmg ให้ลากลง Applications · Windows เปิดโฟลเดอร์ที่มีไฟล์ .exe)

ขั้นตอนปล่อยเวอร์ชันใหม่:
1. แก้ `VERSION = "x.y"` บรรทัดบนของ `remote_desktop.py` → Build (หรือ push ให้ GitHub Actions Build)
2. คัดลอกไฟล์ที่ Build แล้วไปไว้ใน `relay/updates/` บนเครื่อง Relay เช่น
   `NetRemote-macOS-arm64.dmg`, `NetRemote.exe`
3. สร้าง `relay/updates/latest.json` (คัดลอกจาก `latest.json.example`):
```json
{
  "version": "1.2",
  "notes": "• แก้ไข ...\n• เพิ่ม ...",
  "files": {
    "mac-arm64":  "NetRemote-macOS-arm64.dmg",
    "mac-x86_64": "NetRemote-macOS-x86_64.dmg",
    "windows":    "NetRemote.exe"
  }
}
```
   ไม่ต้องรีสตาร์ต Relay — อ่านไฟล์ใหม่ทุกครั้งที่มีการถาม (SHA-256 คำนวณให้อัตโนมัติ)
   แพลตฟอร์มที่ไม่มีไฟล์ จะแจ้งแค่ว่ามีเวอร์ชันใหม่ + ลิงก์ `url` (ถ้าใส่ไว้)

ตรวจสอบได้ที่หน้ามอนิเตอร์: หัวหน้าแสดง "เวอร์ชันล่าสุด" และคอลัมน์ **เวอร์ชัน** ของแต่ละเครื่อง
มีป้าย **ต้องอัปเดต** ถ้ายังใช้เวอร์ชันเก่า · การดาวน์โหลดใช้ `RELAY_KEY` เดียวกัน คนนอกโหลดไม่ได้

## 9. แก้ปัญหา

| อาการ (ในโปรแกรม NetRemote) | สาเหตุ / วิธีแก้ |
|---|---|
| ป้ายแดง "Relay: เชื่อมต่อไม่ได้" — Connection refused | Relay ไม่ได้รัน หรือพอร์ตผิด → ตรวจ `systemctl status netremote-relay` |
| … — timed out | Firewall ปิดพอร์ต 5910 (ทั้งใน VPS และของผู้ให้บริการ) |
| … — Name or service not known | `RELAY_ADDR` พิมพ์ชื่อโดเมนผิด |
| "Relay Key ไม่ถูกต้อง" | `RELAY_KEY` ในโปรแกรม ≠ ใน `relay/.env` |
| "ไม่พบเครื่อง ID … " | เครื่องปลายทางไม่ได้เปิดโปรแกรม NetRemote หรือออฟไลน์ |
| "ID นี้ถูกใช้โดยเครื่องอื่นแล้ว" | กด "สร้าง ID ใหม่" ในโปรแกรม (หรือลบ ID นั้นใน `relay_ids.json` แล้วรีสตาร์ต Relay) |
| "เครื่องปลายทางไม่ตอบสนอง" | Host หลุดจาก Relay ชั่วคราว รอสักครู่แล้วลองใหม่ |
| ไม่ขึ้นแจ้งเตือนอัปเดต | `version` ใน `latest.json` ต้องมากกว่า `VERSION` ของโปรแกรม · JSON ต้องถูกต้อง (ดู log Relay) |
| "ไฟล์เสียระหว่างดาวน์โหลด" | ไฟล์ใน `updates/` ถูกแก้ระหว่างโหลด → ลองใหม่ |
